# 当前范围与待办

更新：2026-09-08。以现有阅读体验作为 **1.0.0 功能基线**。已创建 `v1.0.0` 标签，发布流程见[发布脚本](release/README.md#develop--master-发布脚本)；标签存在不代表远端签名产物已验收。本次新增 1.1.0 解析改进计划，不提前修改应用版本。

## 已形成的功能基线

- Android / iOS 应用、书架、搜索、详情、目录、继续阅读和本地进度。
- TXT / EPUB 文件选择与系统导入、托管副本、去重、删除和离线阅读。
- 分页阅读、排版设置、主题、多语言、EPUB 特殊页兼容及连续切章。
- 图片持久化、有限预取、缓存清理、存储迁移和错误恢复保护。
- 普通 CI 的格式、分析与生成一致性检查；UT 在本地提交前按改动范围执行，不在日常 CI / tag 发布中重复运行。master 是发布中间分支，发布只由 `v*` tag 触发。

完整功能和限制见[README](../README.md)、[阅读器](reader.md)与[本地导入](local-import.md)。完成实现不等于所有设备或发布渠道均已验收，证据统一见[验收摘要](validation/README.md)。

## EPUB 兼容性核查

已扩展扫描用户提供的 35 个文件（34 个不同摘要），修复原 7 项缺口及实际文件中的自闭合 script、条件 CSS、ZIP 打包差异、引用空白等问题：可解析数由 23 提升至 34，余下 1 个因 RSA / AES 声明维持拒绝。508 张独立图片宿主解码、426 项离线回归及 analyze 通过，详见[核查报告](validation/epub-compatibility.md)。旧导入记录不会自动重解析，设备排版 / 裁剪及保留进度的重解析入口仍未由本轮验收或实现；不扩展为完整 EPUB / CSS 支持。

## 1.1.0：解析兼容性与复用

以下任务已纳入版本范围，**均待开发**，按表内顺序执行；本次仅完成规划和第三方比较，不自动启动实现。依据见 [EPUB 库比较](validation/epub-library-comparison.md)。目标是减少重复处理和实际兼容缺口，不承诺替换整个解析器或扩大到完整 CSS / 固定版式 / DRM 解密。

| 顺序 / ID | 工作范围 | 验收与依赖 |
| --- | --- | --- |
| 1 / PARSE-001 | 参考 epub_parser 3.0.1 内部的 OPF、manifest、spine、NCX/nav、资源读取与路径解析，逐项对照现有 EPUB 实现；先形成差异清单，再修复有证据的缺口。WebP 必须检查 AllFiles 与 Images 的分类差异，避免照搬其限制 | 对每个采纳点记录上游版本、源码位置、许可与选择理由；用合成离线样本覆盖编码路径、嵌套目录、同文档 fragment、spine 顺序、图片分类和错误输入。现有 ZIP/XML 限额、边界校验、稳定章节身份不回退；不直接引入 archive/xml 冲突依赖，不强制覆盖版本 |
| 2 / PARSE-002 | 在 PARSE-001 差异清单基础上，对比本地 EPUB 与在线 `lightnovel_chapter.dart` 的 HTML → ContentBlock 处理，抽取确实共享的段落/标题/换行、空白及缩进、文本提取与遍历逻辑；先行为对照再小步迁移两端 | 共享实现留在 data 层，纯 Dart、无网络/存储/Flutter 依赖；通过明确参数或适配器保留站点正文容器、远程媒体规则、EPUB 归档路径/样式/fragment 和特殊页处理。在线不能获得本地文件权限，本地不能因复用发起网络请求；同一 HTML 在共同语义下输出一致，差异有测试说明。保持顺序、blockKey/进度语义与缺图占位，不强行统一不同安全策略 |
| 3 / PARSE-003 | 调研第三方 TXT 阅读器/解析库的内部实现，记录候选及其许可、维护状态，重点比较编码识别、BOM/换行、空白、章节标题启发式、长文本处理和误识别控制；选择有价值的策略增强当前 TXT 解析器 | 不预设存在适合直接依赖的 Dart TXT 库，可参考其他语言开源实现，但需说明适配成本；样本覆盖 UTF-8/UTF-16/GB18030、编码歧义、无标题、正文含“第X章”、中英标题与长行。保持预览确认、原始 code point 章节身份与导入限额；不能为提高命中率静默吞字或破坏阅读进度 |
| 4 / PARSE-004 | 汇总前三项回归、文档及 Android/iOS 验收，形成 1.1.0 解析支持矩阵和已知限制 | 本地执行相关 UT、必要 widget/集成检查及静态分析；在线用离线 HTML fixture，真实书源请求另需显式授权。用户 EPUB 原件只读、不提交正文；原件缺失单列。Android 与 iOS 分别记录导入、目录跳转、图文及恢复阅读结果；无法运行的平台标为待验收。说明旧导入 manifest 不会自动更新，不以重新导入并丢进度作为静默升级方案；若身份/持久化语义必须改变，先设计迁移再实施 |

### 换机继续开发

- 从远端 `develop` 拉取，先检查工作树与本表，再从 PARSE-001 开始；不要从 master 或发布 tag 开发，也不要自动发 1.1.0。
- 比较报告、逐文件摘要、隔离 worker 模板与构建/复跑脚本均随仓库提交，入口为 [tool/epub_compare](../tool/epub_compare/README.md)。`.tooling` 中的 SDK、可执行文件和本机 package_config 不提交，另一台电脑按工具说明重建。
- 35 项原清单本轮仅 31 项可用；电子书原件及绝对路径不随 Git 同步。另一台电脑须自行提供可访问的授权样本路径；按摘要确认是否同一样本，不把缺文件算作解析失败。没有原件时先用合成 fixture 开发。
- 本次交接不包含新解析功能实现。整书下载仍为未来独立范围，不并入这些解析任务。
