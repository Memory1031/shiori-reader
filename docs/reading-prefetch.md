# 阅读预取与离线图片设计

设计日期：2026-09-07。状态：CACHE-001..005 功能已实现，见 [缓存实施记录](cache.md)。Android 模拟器离线冷启动通过，ARM64 真机及 iOS runtime 尚待补测。整书 / 系列下载保持 BACKLOG；本轮仅使用自制 fixture，没有生产 Source 探针。

## 内容单位与后续选择

- 缓存单位是稳定 ChapterKey 对应的源站文章；一篇可能是短章节、完整一卷、特典或另一译本。卷内识别出的“第一话”是同一 ChapterContent 的位置，不发起另一正文请求。
- Catalog ordinal 仅是源站展示顺序，既不证明剧情连续，也不证明属于同一翻译版本。保留原始目录和身份，禁止靠排序 / 标题清洗合并、覆盖两个版本或迁移阅读进度。
- 后续目标分为：用户明确选择；Source 有经过验证的续篇 / 版本关系；未知。前两者可以进入预取，未知时不自动选择目录下一项。当前源尚无足够的关系证据，初版默认采用用户选择路径。
- 卷号、译者、标题相似度只用于候选提示；同卷不同译本、修订版、特典、缺卷、多候选都不能仅凭标题自动认定连续。Source 关系证据未就绪时不为此额外抓取全文分析。
- 目录 / 阅读菜单提供“接下来阅读”选择入口；显示完整原标题、源分组，选定一个后续目标，可更换 / 取消。这是预取选择，不改变当前位置、不自动翻章，也不把下载完成当已读。记录小说、当前文章与目标的稳定身份，独立于阅读进度持久保存；换书、切章或目录变更后重新验证归属与存在性，失效时取消，不回退到 ordinal。
- 原有“下一项”导航须清楚表达目录顺序；存在选定目标时可展示目标标题。未经用户操作不自动打开另一版本。完成当前目标后不连锁推导下一本，禁止递归全系列预取。

## 调度顺序

所有 HTTP（包括媒体定位元数据请求）共用既有限流 / 并发 / deadline / 重试策略。全局最多2个在途，后台最多1个；不增加独立图片下载网络栈。

| 优先级 | 内容 | 触发与行为 |
| --- | --- | --- |
| 最高 | 用户当前请求的正文、可见图片 | 立即读取本地，缺失才联网；不等待整章图片完成 |
| 高 | 当前阅读位置附近图片 | 当前文章 ready 后按阅读位置排序，先准备接下来4张及刚看过的1张（已有缓存跳过）；跳转后重排 |
| 普通 | 当前文章其余图片 | 前台请求满足后串行落盘，最终覆盖该文章全部插图；即使文章是整卷也允许 |
| 低 | 一个已确认的后续文章正文 | 当前文章 ready 且用户明确选定后即可空闲调度；Source 明确关系的自动目标则在当前进度达到约70%后启动，当前图片始终优先 |
| 最低 | 后续文章图片 | 正文成功后先前4张，再在当前文章图片已齐且预算允许时补剩余图片；不得阻塞当前阅读 |

新前台请求可提升共享中的同资源任务；不得因取消后台消费者而终止仍有前台消费者的请求。不同资源的后台排队先撤销 / 让位；无法安全抢占的单个在途请求遵守原截止时间，不反复取消重下。保存已成功文件后再继续，失败不清空整批。

初始后台会话预算建议64 MiB实际网络字节、200次HTTP尝试，当前 / 后续文章合计且包含定位与重试；单资源仍遵守既有大小限制。该数值由 CACHE-001 fixture 校准，不宣称整系列大小可预知。预算耗尽暂停，不因切章、滚动或短暂前后台切换重置；用户明确“继续缓存”才能开启新批次。前台真实阅读请求不受此后台额度限制，但仍受单资源、网络和磁盘限制。后台不自动唤醒、失败无无限重试；429按Source冷却，权限错误停止对应任务，cacheOnly / 明确离线 / App inactive 停止网络预取。

## 图片显示与持久化

1. 首先完成 CACHE-003：封面 / 插图以稳定 MediaRef 和版本证据索引托管文件；写暂存、校验、原子提交、索引更新。签名 URL 不是缓存身份，不持久化临时凭证。
2. 成功加载的图片重启后优先读磁盘。文件存在且校验有效才计入“图片已缓存”；仅有引用、HTTP成功或仍在写入都不算。坏图只失效本项，不能清整个书籍缓存。
3. 下载预取与解码预热分开：全部插图可落盘，但只对可见 / 近邻页的极少数图片按DPR与像素上限预解码，共享有界解码预算。禁止把整卷原尺寸图片全放RAM。需要明确租约释放及尺寸 / 主题 / 视口变更后的缓存键，优先使用仍有效的已显示图，减少占位闪烁。
4. 从可信元数据或图片头获取尺寸，按已知比例预留空间；未知尺寸不伪造比例。图片完成后的重排保持当前语义阅读位置，不能把读者推到另一页。保留占位和单图重试，不让一张失败图阻塞文字或其余插图。
5. 不承诺首次离线或源站故障时能显示从未成功获取的图。目标是缓存成功后避免重复联网，以及阅读时尽早准备后续图片；失败仍需清楚且安静地反馈。

## 容量、状态与清理

沿用256 MiB持久payload初始总预算（正文 / 元数据64、图片192），后续测量再调。磁盘预算不等于内存预算，也不等于承诺可装下整系列。当前文章正文、活动图片及近邻工作集保护；该文章远处图片优先保留但不全部永久pin，避免整卷超过预算造成淘汰死锁。超预算停止低优先级预取，不能反复下载刚被淘汰的同一批图；一次批次记住淘汰 / 失败 / 已尝试项，需求变化或用户明确重试后再尝试。

目录 / 缓存Sheet可显示“正文已缓存”“插图12/15”“正在准备接下来阅读”“已暂停 / 部分失败”，状态按实际文件校验计算；不会常驻遮挡正文。插图引用总数未知时不得显示100%或“完整离线”。状态、操作与设置均提供中英文。当前及后续预取分别可关闭，后续目标随时可取消；关闭不删除成功缓存。

按书或全部清理递增generation、取消后台任务并禁止旧回调回填；不删书架、进度、阅读偏好或用户选定的阅读顺序。清理后不自动重建后台队列，须新阅读需求或用户明确恢复。缓存删除、文件缺失或淘汰立即使完整状态失效。

## 验收与实施拆分

- CACHE-001：总量 / 后台会话预算、优先级、工作集保护、无淘汰重下载循环。
- CACHE-002：整卷文章缓存与版本隔离、stale / 清理一致性，不改变当前阅读快照。
- CACHE-003：托管图片、稳定引用、失败隔离；近邻解码预热与占位重排保持位置。
- CACHE-004：真实图文缓存状态、暂停 / 继续 / 重试、清理和飞行模式冷启动。
- CACHE-005：目标关系判断 / 用户选择及持久化、当前文章全部图片与一个后续目标的分级调度；依赖 CACHE-003。
- 离线fixture覆盖：整卷混排；下一项是同卷另一译本；特典夹在两卷间；缺卷 / 多候选；无Source关系；用户改选；目录刷新移除目标；当前章跳转；一张图失败；429 / 磁盘满；大于预算的文章；共享请求提升与取消；清理晚响应；退出 / 重启后文件复用；大字号 / 横竖屏位置稳定。不得以网络请求完成替代图片解码 / 页面显示验收。
- Android须真实缓存后飞行模式冷启动并验证部分 / 全部图片；iOS沿用兼容设计，运行验收归 IOS-005，无Mac不声称通过。真实Source验证另需明确请求预算，不使用旧授权。
