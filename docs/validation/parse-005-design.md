# PARSE-005：重新解析与进度迁移设计

2026-09-09。状态：用户已确认实施，代码与验证见[结果报告](parse-005.md)。本文保留实施前的现状和设计依据，不作为当前行为说明。

## 已核实的现状

- `ManagedLocalBooks` 串行拥有托管文件；首次导入通过目录改名后 SQL 发布，当前固定读取 `<digest>/manifest.json`。数据库 schema v3 没有解析代次或活动 bundle 指针。
- EPUB `_read` 会从原件重新解析，然后用新 catalog/chapters/navigation 替换内存记录，尽管磁盘 manifest 未变。这与“旧导入不自动重解析”的预期不一致；必须与迁移一起修正，不能继续把新正文直接配给旧进度。
- `LibraryRepository.saveProgress` 已有 generation/sequence 原子晚写保护，可沿用；迁移不能先清进度再补写。
- 本地 `LocalReadingRepository` 的更新流为空。仅清存储缓存不足以刷新已打开 Reader；必须处理旧控制器和读取会话。
- EPUB 按 path 拒绝重复 spine，导航及 presentation 都按资源路径对应单章。目前没有 occurrence 模型。
- 旧 manifest 没有保存 TXT 选择编码或原始文件名，不能可靠猜测原选择。

## 发布与恢复

1. 保留书籍摘要及 `original`，不复制第二份长期原件。新增不可变 `revisions/<bundleId>/`，包含 manifest、媒体与特殊页呈现；bundleId 使用内部随机标识，不能来自用户路径。
2. schema v4 给 local_books 增加可空活动 bundle 字段及解析版本；NULL 表示旧根目录格式。升级只增加字段，不自动重解析、改进度或移动原件。保留 schema v1/v2/v3 快照，验证各旧版本升级。
3. 显式请求后验证原件摘要，在 staging 解析、校验和落盘。沿用输入/媒体/manifest 限额，特殊页总量也保持有界。文件全部就绪后改名到 revisions；此时 SQL 仍指向旧版本。
4. 读取旧进度及 generation/sequence，纯函数在 worker 中计算迁移。最终 SQL 事务重新检查活动 bundle 和进度 stamp：若期间阅读/清历史改变进度则终止本次发布并提示重试，不用旧快照覆盖用户新操作。
5. 同一个 SQL 事务切换 bundle/hash/title、更新已有书架快照、写迁移进度并提升 generation。保留 importedAt、addedAt、lastReadAt；没有书架或进度则不新增。所有像素布局提示清空。completed 仅在明确匹配原完成位置时保留，近似恢复不推断已读完。
6. 提交前取消/失败保留旧指针、旧进度及文件；提交后返回真实成功。SQL 是唯一可见性边界，不依赖两次目录改名模拟事务。
7. 启动先成功读取数据库，再清理 staging 和未被活动指针引用的 revisions；数据库不可用时不回收。旧根目录资源在首次迁移成功且无活动读取后回收，保留 original；不会长期堆积所有历史版本。清理失败记录 cleanupPending，下次启动重试。
8. 崩溃测试分别覆盖暂存中、改名后提交前、事务中、提交后清理前；必须分别恢复旧版或新版完整数据，不接受混合状态。

实现时文件路径需沿用符号链接与包含性校验。活动版本损坏时保留文件并报错，不把它当作未索引垃圾删除。媒体仍按内容摘要校验，读取只访问已发布版本。

## 阅读位置迁移

纯 Dart、确定性、有界；输入旧/新 LocalBookContent 和旧 ReadingProgress，输出新位置与封闭结果等级（无历史、精确、近似）。不写存储、不携带路径或正文诊断。

匹配按以下顺序：

1. 同章节身份、同 blockKey；核对旧 revision 和块是否真实存在。重复块不能仅凭 occurrence 数字宣称精确，需核对邻近语义上下文。
2. 同章文本/图片语义匹配，允许仅对齐/缩进改变。文本位置按 Unicode code points，验证局部前后文；图片优先同媒体摘要及邻近上下文。
3. 块拆分/合并：对受限邻近文本窗口建立位置对应，不把全文拼成无界模糊搜索；多处相同文本无法唯一定位时保守降级。跨章只接受唯一上下文证据，不按同名标题直接断言同章。
4. 同章仍存在但无法匹配时按 chapterFraction 近似；章节消失且无唯一文本证据时选旧 ordinal 限定后的最近可读章起点，明确报告近似恢复。不会默默清进度或声称回到原行。

旧 EPUB 进度可能已来自运行时派生内容：先检查磁盘旧版本是否匹配 progress.contentRevision；不匹配时不能伪造“旧正文位置”。可使用新版本精确身份证据，否则明确近似。新 manifest 会记录解析版本，停止普通读取时替换语义正文。

## EPUB 重复 spine

- EPUB 3 同资源每次出现都保留阅读章节；第一次沿用 `epub:<path>` 身份，后续使用独立 digest kind + `[path, occurrence]`，避免与合法路径字符串碰撞。occurrence 从 0 计数，按解析后的资源路径分配；fallback alias 不制造第二份资源内容。
- EPUB 2 重复引用保持拒绝。包版本必须显式识别，未知版本不猜测套用 EPUB 3 规则。
- 资源解析/媒体可复用，章节身份与 ordinal 分开；三次出现必须三个 ChapterKey，presentation 也按出现映射。
- 普通 nav/NCX 的 href/fragment 没有 occurrence 信息，统一指向首次出现，作为明确产品策略；连续阅读按 spine 三次呈现。辅助链接返回当前 occurrence 归 PARSE-008，不在此轮扩展。
- 原有唯一资源章键不变；旧首次出现映射到新首次。新增前置重复项导致 occurrence 改变时仍需上下文判断，不宣称永久稳定。

## 入口、合同与生命周期

- 新增独立 LocalBookReparse 能力及不可变结果，不扩大删除接口职责；实现复用 BookDecoder 的解析回调、编码确认与 CancellationToken。
- 本地文件管理每本书菜单新增“重新解析”，中文/英文文案齐全。说明保留原文件、尽量恢复位置；成功显示精确/近似结果，近似时明确请检查当前位置。
- TXT 旧记录重新提供严格编码预览与手选，不默默沿用无法证实的编码。新版本记录实际选择编码；TXT 标题保留旧显示名，避免用临时文件名覆盖书名。
- 操作可取消；离开页面取消尚未提交的工作。解析忙状态禁止同书的重复操作；业务层保持单一文件所有者。
- 不允许活跃 Reader 在迁移期间重新获取新 generation 后写旧正文。实施书籍级维护状态，开始前关闭/失效该书 Reader，提交后清仓库/控制器缓存并重新加载。对直接接口调用仍做数据库版本与 stamp 仲裁，不能只依赖 UI 禁用按钮。
- 本地读取通知或显式失效事件要覆盖 catalog、chapter、navigation、presentation；只刷新书架不算完成。失败后重新打开仍读旧版本。

## 实施顺序与验收

1. 明确并确认本文迁移设计。
2. Domain 迁移结果、位置匹配纯函数和合成测试；文档合同同步。
3. schema v4、不可变 bundle、发布/取消/崩溃/晚写保护及旧版本迁移测试。
4. EPUB occurrence 与停止读取时隐式替换语义；首/后续 occurrence、目录 fragment、EPUB 2 拒绝测试。
5. 管理入口、编码选择、Reader 失效与中英文提示，widget 测试。
6. 离线回归、生成一致性和 analyze；汇总实际证据。按既有用户要求不自动启动模拟器，设备验收另记，不以 UT 代替。

必测：无进度、精确块、缩进变化、拆分/合并、重复文字、删章、图片、emoji/CRLF、TXT 编码重选、原件损坏、磁盘/SQL 失败、取消、并发进度更新/清历史、旧 session 晚写、重启垃圾回收和三次 spine。实际源码与测试完成前 PARSE-005 不标完成。
