# DB-003 迁移与损坏保护

2026-09-08。当前用户库 v3、缓存库 v2；没有历史正式发布包，本轮使用保留的开发 schema 快照，不宣称正式版本间升级验收。

## 修复与验证

- 用户库 v1/v2 → v3、缓存库 v1 → v2：直接读取保留 snapshot 的 fixed_sql 重建旧库，不截取当前 SQL。比较书架、进度、会话及已有预取设置的所有旧字段；领域 Repository 能读取原书名、blockIndex=17 / fraction=.25。
- 测试专用 Migrator 在后续建表时抛错，复现前序新表未回滚的问题。升级现在将 DDL、完整性检查和 user_version 写入放在同一事务中；失败后旧表、旧行和版本号保持一致，解除故障可重试。没有 drop 用户表或自动删库重建。
- 不兼容缓存曾被离线列表误列为可读：列表只检查 JSON，却没有检查外层 codec_version。现在两层版本均检查，坏 envelope / 不兼容记录不出现在可读列表。清缓存只失效缓存，书架、会话序列、预取设置及托管原件哨兵字节保留。
- 用户 / 缓存文件损坏时，独立临时文件打开返回 database Failure；原损坏字节不变，托管文件保留。缓存与用户库没有跨文件事务：用户库升级成功而缓存打开失败时，保留有效的已升级用户库。
- 应用外观与阅读排版使用独立 preferences，不由 SQLite schema 迁移改写；既有偏好迁移与保存测试纳入全量回归。
- 修复一个旧测试的不确定性：EPUB 重复导入测试现在复用相同字节，避免 ZIP 时间戳变化使样例变成不同文件。生产去重语义未改。

新增 8 项专项测试位于 `test/data/local/migrations/`；完整离线回归 **386 项通过**。所有测试使用临时库和自制数据，无在线 Source 请求。受支持的 codec 仍为 v1，不虚构不存在的历史 codec 转换。

Android 实测：BMH-AN10 / Android 12（API 31）/ arm64-v8a，Profile 探针在新建临时目录执行 user1、user2、cache1 三条升级并重开，报告均为 PASS。临时库已由探针清理，结果保存于本机 `db003-android-report.json`。真机没有注入损坏 / 失败；这些场景由主机专项覆盖。正式 Release 构建成功（本地开发证书，不是签名 RC），analyze 无问题。

## 恢复策略与证据边界

打开失败保留原文件并明确报错，不自动恢复备份、不清空书架，不把用户库当缓存。缓存文件整体损坏导致启动失败时，本轮仍保留错误，不新增自动删缓存库逻辑；单条不兼容缓存可通过现有清理功能失效。当前没有用户损坏记录的自动修复 UI。

排障应先退出应用，保全数据库及存在的 WAL/SHM、preferences、托管原件和 manifest，在副本上检查；只有用户明确选择时才从已核验备份恢复。不要把删除 users.sqlite 当作通用修复办法。开发隔离目录的显式 reset 与生产恢复是不同操作，本轮未添加生产 reset，也未删除手机现有数据。

macOS 是本轮实际主机；Windows 未运行。iOS 仅复核共享 Drift / SQLite API，无新增依赖或平台分支，文件 / migration runtime 仍留 IOS-005。全局备份恢复和磁盘耗尽仍遵循此前用户决定，本任务未重新执行这些已跳过项目。

本机证据 `.tooling/evidence/db003-*`：baseline / codec-baseline 为修复前失败记录；migrations / tests / analyze 为回归；profile-build / release-build 为构建。Android 探针使用 `integration_test/database_migration_smoke.dart`，快照以 Base64 dart-define 输入，不加入生产 assets。探针仅访问新建临时库，结束删除该目录，留下独立结果 JSON 供读取；正式入口不包含探针。
