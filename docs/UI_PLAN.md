# Shiori UI 规划

日期：2026-09-07。适用于 Android / iOS。本文是后续 UI 实现的共同依据；本轮只编写规划，不修改 Widget、主题、持久化格式或阅读行为，也不开始 READER-006。

## 1. 产品方向与决策状态

**日系文库感、安静的编辑排版、封面主导、阅读器尽量隐形。** 用暖纸底色、清楚的层级和少量灰梅粉建立辨识度。Material 3 继续提供控件行为、焦点、反馈和基础无障碍，Shiori 自己定义颜色角色、排版、密度与内容布局。

| 现在确定，后续页面遵循 | 候选值，Theme Lab 验证后收敛 | 暂不做 |
| --- | --- | --- |
| 保留 M3；内容直接排在页面上，避免 Card 套 Card | 具体色值、封面圆角、控件密度、标题字号 | 替换整套组件库、全页模糊封面背景 |
| 书架为默认首页；封面是网格的视觉主体 | 不同屏宽的网格列数、详情头部高度 | 社区、账号中心、没有数据依据的排行榜 |
| 应用主题和阅读配色分开；正文不承担品牌展示 | 纸白 / 暖纸 / 夜间的实际对比与阅读感受 | 花纹纸、绿色“护眼”承诺、硬件亮度控制 |
| 中英双语、系统大字、横竖屏、可访问操作从起步支持 | 动画曲线、少量角色插画的画风 | 自定义字体包、动态取色依赖、复杂拟真翻页 |
| Domain / Repository 不受视觉规范影响 | Token 类名及按需抽取的组件名称 | 为假想页面先造完整设计系统框架 |

色值与尺寸是本项目的设计候选，不是平台 API 事实，也不代表已经通过视觉评审。Theme Lab 用可运行样板验证；业务行为以 TASK_PLAN、domain、contracts 为准。本文明确的新产品方向更新旧 UI 草案，历史任务的验证记录保留。

## 2. 信息架构

首版采用两个一级入口：**书架 / 发现**。首次和正常冷启动落在书架；不自动打开正文、弹出导入或发起发现请求。系统外部打开文件属于显式意图，按导入流程处理，保留返回原页面的路径。

| 页面 / 入口 | 结构与主要动作 |
| --- | --- |
| 书架（默认） | 顶部 Shiori + 搜索 + 添加菜单；添加菜单包含导入 TXT / EPUB；设置放溢出菜单。继续阅读一项 + 我的书架。最近阅读列表是次级入口，不是第三个 Tab |
| 发现 | 顶部搜索入口 + 当前书源说明；仅显示源已经支持的内容分区。supportsDiscover=false 时保留搜索和书源信息，不请求不存在的发现接口、不画空排行榜。离线时书架 / 本地导入仍可用 |
| 搜索 | 由书架或发现进入同一页面，返回来源页面；明确书源范围。输入框、显式搜索按钮 / 键盘提交、结果列表；没有自动输入搜索 |
| 详情 | 封面与元信息、唯一高强调阅读动作、次要收藏动作、简介、目录入口 / 目录预览 |
| Reader | 独立阅读页面，不保留底部一级导航；目录、排版设置和前后章操作属于阅读上下文 |
| 设置 | 从书架菜单进入：外观 / 语言、阅读默认偏好、存储、书源与关于。无个人中心、头像或登录占位 |
| 导入 | 系统选择器或外部打开 / 分享 → 格式与文件确认 → 必要的编码预览 → 可取消进度 → 加入书架并提供开始阅读。重复导入指向已有书，不另建副本 |

“发现”作为稳定导航目的地，即便暂不提供推荐，也要有可操作的找书入口。不能只因为 UI 画了分区就扩大 Source 能力。搜索结果及目录选择携带现有不透明 key；不通过标题定位书或章。

书架默认首页会调整 HOME-001 的职责：它负责根导航、默认书架承载和发现页；书架本体仍由 SHELF-001 实现，收藏 / 最近阅读联动由 SHELF-002 实现，继续阅读恢复闭环由 PROGRESS-001 实现，避免复制三套“首页书架”。

## 3. 视觉规范候选

### 3.1 颜色与表面

| 语义角色 | 浅色候选 | 深色候选 | 用途 |
| --- | --- | --- | --- |
| pageBackground | #FAF8F4 | #1B181C | 大面积背景 |
| surface | #FFFCF8 | #252126 | 弹层、确有边界的容器 |
| textPrimary | #302C2B | #EEE7EB | 标题、主要正文 |
| textSecondary | #70686B | #BEB3BA | 作者、来源、次要状态 |
| accent | #95506D | #D8A1B9 | 主动作、选中状态、小范围品牌点缀 |
| separator | #DED8D5 | #454047 | 装饰分隔；不得作为唯一可操作边界 |

默认关闭系统动态配色对品牌调色板的覆盖；仍跟随系统明暗。主题工厂把语义角色映射到 ColorScheme 和组件 Theme，不把 fromSeed 的所有默认染色原样铺满界面。错误、警告、成功使用独立语义色并伴随文字 / 图标；不拿灰梅粉同时表示错误。

普通文字目标对比至少 4.5:1，可操作图标 / 边界目标至少 3:1；候选颜色需要工具计算与真实组合检查，不能凭肉眼宣布通过。封面衍生色只允许出现在详情头部，不影响文字对比、按钮语义或正文区域。

### 3.2 排版

使用系统字体及系统 CJK fallback；首版不附带字体文件。UI 的中文 letterSpacing 默认 0，英文品牌字样可单独微调，不能把英文全大写标签样式套到中文。正文与 UI 使用独立文字样式。

| 角色 | 初始字号（logical px） | 字重 / 行高方向 |
| --- | --- | --- |
| 小说详情标题 | 24（候选 22–26） | 600；多行自然增长 |
| 页面标题 | 20 | 600 |
| 分区标题 | 17 | 600 |
| UI 正文 | 16 | 400；约 1.5 |
| 元信息 | 14 | 400；约 1.4 |
| 次要说明 | 12 | 400；不承载唯一操作或重要状态 |
| 阅读正文 | 20，保持现有 14–32 范围 | 400；默认行高 1.7，保留用户设置 |

封面标题最多两行，支持通过点击详情、无障碍标签读取完整标题；详情标题不强制单行省略。作者缺失可省略该行，不填“未知作者”占据封面下的大量空间。多语言下按钮允许变宽、换行或纵向排列，不整体缩小字号来塞进固定高度。

### 3.3 间距、圆角、封面

- 基础间距档位：4 / 8 / 12 / 16 / 20 / 24 / 32；手机页面水平留白初值 20，小屏可用 16，分区间距 24–32。
- 封面圆角初值 8，普通控件 10–12，Sheet 顶部 20；圆角表达层级，不要求所有控件都变成大胶囊。大多数内容不加阴影。
- **封面展示框宽高比统一 2:3**，作为产品网格规则，不宣称所有原图都符合比例。缩略图允许 cover 裁切；详情完整封面与正文插图采用 contain，长按 / 点击查看大图的能力按任务接入。原图比例不写入持久书籍身份。
- 缺封面使用同尺寸的纸色书封占位 + 标题 / 简单书签符号；加载、成功、失败尺寸一致，不因到图改变网格高度。
- 首版手机网格目标 3 列，窄屏或大字降为 2 列；按可用宽度、最小封面宽度约 96 和文字缩放计算，不按设备型号硬编码。平板增加列数并限制页面最大宽度，保持懒构建。

### 3.4 自适应

以实际可用宽度分级（候选：<600、600–839、≥840），不是平台判断。窄屏为单列详情 / 底部导航；较宽屏详情可采用封面与元信息并排，根导航可转 NavigationRail。组件保留相同语义和 route，不建另一套平板业务逻辑。

Reader 在宽屏居中限制可读行宽（初值约 680 logical px），继续使用同一单列原生正文，不在首版引入双栏分页。行宽、SafeArea、字号、文字缩放、横竖屏变化都走现有语义锚点恢复。具体最大宽度先在中英长段 / 日文标点 fixture 上比较。

## 4. 关键页面蓝图

### 4.1 书架

从上至下：页面标题 / 工具 → 有历史时的继续阅读 → 我的书架分区和排序入口 → 封面网格。继续阅读使用一组封面 + 文案 + 阅读动作，以留白划分，不另套厚卡片。无历史时整段省略；空书架显示去搜索和导入文件两个真实入口。

网格单元仅封面、两行书名与必要元信息。小状态徽标必须有事实来源：当前没有更新检测契约，首版不显示 NEW。本地文件可显示“本地”文字标识；缓存正文与插图完整度分开表达，不能因为有封面就显示可离线阅读。

默认按既定最近阅读规则排序；长按或溢出菜单提供移出书架、详情等操作，不独占于手势。在线书“移出书架”可撤销且保留历史 / 缓存；本地书“移出书架”与“删除已导入文件”分开，后者说明影响并确认。

继续阅读显示书名、卷章（仅有真实元信息时显示）和“本章约 36%”形式。现有 chapterFraction 是按块计算的粗略章内比例，不能标成全书百分比；completed 表示已看到章末，不等于全书读完。

### 4.2 发现与搜索

发现分区以封面和短标题为主，不增加营销横幅或循环轮播。没有已验证推荐数据时，不做假内容填充。搜索结果优先使用封面 + 标题 / 作者 / 少量来源信息的纵向列表，便于长标题辨认。

必须区分：未提交搜索、搜索中、无结果、已有结果后翻页失败、没有更多、源不支持、网络错误与访问受限。翻页错误放列表底部，保留既有结果；搜索中保留输入框和返回。stale 内容继续显示，刷新失败使用局部提示。

### 4.3 小说详情与目录

头部使用完整封面 + 很浅的有色背景，正文区回到纸色。首版使用统一低饱和色；动态取色列入以后可选项，不新增请求或阻塞内容显示。封面到详情可使用 Hero，使用书籍身份与上下文构造唯一 tag；从多个位置打开同一本书不能发生 Hero 冲突。

阅读是唯一高强调 CTA：有进度显示继续阅读，无进度显示开始阅读；加入 / 移出书架用次要动作。窄屏可固定底部操作区，正文必须给操作区留安全空间；大字下转为可增长布局。阅读失败保留详情与目录，不假改新章进度。

CatalogView 共用数据与交互：详情内可预览目录并进入完整目录；Reader 中窄屏使用接近全高的 Sheet，宽屏可用侧面板。长目录懒构建、当前章高亮、支持卷展开 / 折叠与定位当前章。EPUB 嵌套目录 / fragment 保留缩进和对应定位，重复章名仍按 key 区分。目录不是按标题拼接出来的静态列表。

### 4.4 阅读器与工具栏

稳态正文不显示品牌标志、彩色正文、装饰容器或永久模式切换条。默认左右翻页，保留上下滚动；模式选项移入排版 Sheet。当前 READER-004 / 005 的界面是功能基线，不能作为最终阅读器视觉规范。

目标行为：新安装首次进入 Reader 可显示一次简短操作提示；后续默认隐藏 Chrome，不按阅读计时反复自动显隐。点击中间区域切换 Chrome；左右翻页时两侧区域用于翻页，滚动模式保留拖动。显示 Chrome 时有明确的目录、排版、返回及前后章操作；屏幕阅读器和外接键盘必须有显式按钮，不只依赖无标签热区。

显示 / 隐藏 Chrome 使用同一正文布局边界。首版 UI 改造继续保留稳定的上下安全留白，以免工具栏遮挡首可见锚点；不把留白误当可持久像素。不为“更沉浸”在本轮重写分页器、锁横屏或隐藏系统栏。长标题省略只发生在工具栏，章节正文标题正常排版。

底部比例标注为章内粗略进度；没有完整分页计数就不显示“第 12 / 300 页”，也不先排完整章求总页数。可跳转进度条只在语义定位能力验收后提供，不先放一个假滑块。

未保存、内容更新降级、当前图失败都保留低干扰且可访问的反馈；隐藏 Chrome 时也要能发现重要未保存状态，例如短时提示配合显示操作栏中的重试入口，不常驻大红横幅。

## 5. 应用明暗与阅读纸色：提前拆清

| 设置维度 | 值 / 默认 | 影响 |
| --- | --- | --- |
| 应用外观 | 跟随系统（默认） / 浅色 / 深色 | 书架、发现、详情、应用设置 |
| 阅读明暗 | 跟随系统（默认） / 浅色 / 深色 | Reader 当前明暗，与应用外观独立 |
| 浅色阅读纸色 | 纸白（默认） / 暖纸 | Reader 为浅色时的背景 / 文字组合 |

对用户展示纸白 / 暖纸 / 夜间三种阅读预览；夜间预览对应阅读明暗=深色，纸白或暖纸预览对应浅色及所选纸色，另有“跟随系统”开关。开启跟随后，系统亮时使用记住的浅色纸色，暗时使用夜间；控制可见状态必须与实际生效组合一致。首版不增加独立 AMOLED 配色。

当前 ReaderSettings v2 的 themeMode 继续表示阅读明暗。未来 UI-002 增加浅色纸色字段时使用 v3，v1 / v2 迁移补 paper，保留字号、模式、边距、行高与原 themeMode；未知版本仍不覆盖。应用外观 / 语言使用独立 AppSettings 存储边界，不把字符串 locale 或颜色对象塞进 ReaderSettings。旧实现把 ReaderThemeMode 借作 appThemeMode，是需要拆开的现状；没有独立应用偏好时应用先默认跟随系统，不擅自将旧阅读偏好解释为用户对全 App 的选择。

颜色 hex、圆角、动画时长属于 presentation tokens，不入 Domain 或数据库。持久化只存用户偏好语义，不存 ThemeData / ColorScheme / TextStyle。本轮只定迁移方向，codec 及消费者在 UI-002 / 应用设置对应任务中一起修改与验证。

## 6. 组件和代码边界

单向来源：**Shiori 语义 tokens → ThemeData / ThemeExtension 与组件 Theme → feature UI**。M3 不是再包在 tokens 外的第二套主题源。颜色等随主题变化的扩展采用 ThemeExtension；静态 spacing / radius 常量可以保持简单。ThemeExtension 的 copyWith / lerp 支持自定义主题字段及过渡，实施时核对项目固定 SDK。[Flutter API](https://api.flutter.dev/flutter/material/ThemeExtension-class.html)

| 建议落点（实现时按需创建） | 职责 |
| --- | --- |
| lib/app/theme/ | 颜色、排版、间距、圆角、动效、封面规范及统一主题工厂；逐步迁移现有 app/theme.dart |
| lib/shared/widgets/ | 仅抽取真实复用的 BookCover、BookGridItem、状态展示、分区标题；保留无障碍语义 |
| lib/features/reader/ | Reader 配色解析、排版 Sheet、Chrome；测量和绘制消费同一正文样式 |
| lib/dev/ui/theme_lab/ | 离线样板、场景切换、候选视觉比较；仅开发入口引用 |

不逐个包装所有 Material Button / Dialog；优先用组件 Theme。BookCover 借用 ImageRepository，尺寸 / fit 可配置，图片访问规则留在数据层。目录和导入页使用既有领域契约，不为界面顺序发明重复模型。

需要提前治理的现状：ReaderContentView 内独立创建默认 ThemeData、局部 TextStyle 和 gutter；全局 appTheme 只有 seed；AppController 借 ReaderSettings 控制应用主题；Chrome 常驻模式 Chips。这些均有明确迁移任务，后续新业务页面不要复制该临时写法。READER-006 只消费排版变化与语义锚点，不依赖灰粉色、工具栏高度或具体 Sheet 结构。

## 7. 状态、角色、动效与可访问性

加载用稳定占位、局部进度或有限 skeleton；优先保留已有内容。减少动画模式下停止 shimmer、spring 和非必要 Hero，状态仍清楚可见。页面路由保留现有 Android / Cupertino 返回行为，不统一替换为自定义淡入路由。

“栞”可用于空书架、无搜索结果等有情绪意义的空状态，面积克制；网络错误优先文字与恢复操作，角色可选。无正式角色设定或资产时用简单书签图形，不把“粉发栞”当已有素材。人物不用于循环 loading，不出现在正文，不为了装饰打断错误信息；资产许可和文件体积在接入时记录。

动效预算候选：普通反馈 180ms、Chrome 淡入淡出 180ms、封面 Hero / Sheet 约 220–250ms。不做逐项入场、普遍弹簧或自动轮播；删除书架项的动效不能延迟撤销入口。颜色过渡不对正文尺寸做动画，以免持续触发布局恢复。

发布验收必须覆盖大文字缩放、可理解的控件标签、TalkBack / VoiceOver 与可撤销操作；Flutter 官方也将这些列入无障碍检查。[Flutter 无障碍说明](https://docs.flutter.dev/ui/accessibility)

项目基线：触控目标至少 48×48 logical px；语义朗读为标题 → 作者 / 状态 → 动作，封面装饰不重复朗读；选中状态有图标 / 文案，不只靠颜色。字体缩放至少测 1.0 / 1.3 / 2.0，支持更大缩放时仍能滚动到关键操作，不全局 clamp 系统字号。简体中文与英文使用 gen-l10n，支持日文内容与 CJK 标点。日期 / 数字使用 locale 格式；不将“章内约百分比”翻译成全书已读百分比。

## 8. 落地顺序与验收

### UI-001 — Tokens 与 Theme Lab（已实现）

前置 CORE-004、DEV-002，均已完成。实现最小 tokens 和开发专用 Theme Lab，包含书架、详情、Reader 三个同时采用同一规范的高保真离线场景。使用自制 / 有授权封面；首版不生成角色资产、不连接真实 Source、不修改数据库。开发样板中的假交互明确标注，不作为生产闭环验收。
