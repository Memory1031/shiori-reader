# Shiori 测试策略与维护规范

测试质量取决于有效的回归保护、确定性、执行成本和维护成本，不以用例或文件数量衡量。新增、修改或删除测试前，先确定需要保护的行为、独立风险及已有覆盖。

## 选择验证层级

优先使用能够验证实际行为的最低成本层级。

| 内容 | 首选验证 |
| --- | --- |
| 纯函数、数据映射、格式化 | 纯 Dart 单元测试 |
| Controller 状态迁移、取消与互斥 | Controller 单元测试 |
| Repository、数据库、文件与缓存契约 | 数据层测试与确定性 Fixture |
| 点击、确认、焦点、菜单和导航 | Widget 测试 |
| 字体、视觉层级及普通布局效果 | 实际 Flutter 组件渲染检查 |
| WebView、原生插件、系统安装或平台生命周期 | 对应平台的集成、模拟器或设备验证 |

不要为字符串映射启动完整应用，也不要在完整页面中重复 Controller 的整个状态机。Widget 测试只验证必要的状态呈现和操作接线；真实导航、持久化与资源释放则必须在能覆盖该调用链的层级验证。`TargetPlatformVariant` 只是 Flutter 平台变体，不等于原生设备测试。

## 编写有价值的测试

普通交互优先覆盖正常操作、取消或失败没有错误副作用，以及关键边界。通常少量场景足够，但不设机械数量上限。一次交互过程中的多个约束可以集中断言；独立失败原因应保持可定位，不把无关流程塞进一个长测试。

间距、颜色、边框、圆角、普通图标、静态描述或没有新状态的布局微调，不默认新增或运行自动化测试。执行格式检查和静态分析，并按 UI 规范检查实际渲染；必要时选择窄屏、英文长文本或大字体。

以下风险仍需要自动化保护：点击范围与可访问性、溢出阻断关键操作、重要按钮被遮挡、条件显示与禁用状态、删除确认、取消与保存失败，以及影响阅读器分页正确性的布局。截图不能替代这些行为断言。

测试默认离线、使用合成或获授权的 Fixture。异步工作使用可控完成点、取消 token 或虚拟时钟，不用任意等待掩盖竞态。测试持有的数据库、订阅、进程与资源租约须在失败路径同样释放；先关闭占用资源，再清理临时文件。不要泄露服务端正文、凭据或私人书籍数据。

## 控制矩阵与重复覆盖

不默认执行语言 × 尺寸 × 主题 × 平台的笛卡尔积。代表场景按独立风险选择，例如中文普通尺寸验证基础交互、英文窄屏大字验证溢出、Windows 宽屏验证桌面菜单和断点；这些是候选，不要求每次全部采用。

只有真实平台分支、不同交互或 API、已经确认的平台回归，才扩大平台矩阵。断点测试应验证两侧的行为与状态保留，不为相邻尺寸反复执行同一完整流程。没有字体或布局风险时，不重复验证多语言的同一状态机。

删除或合并前，核对实际调用链、输入、状态迁移和断言。可精简相同覆盖、无差异的平台变体、只改变无关语言或尺寸的流程、普通静态元素存在检查，以及可在更低层级验证的页面流程。截图入口可以保留为显式视觉检查，不能用仅有绘制而没有独立约束的默认测试充数。

保留的用例必须仍能识别原有问题。不得仅凭名称相似、文件长度或数量目标删除测试；不同 EPUB 结构、算法边界和真实回归样本，即使外观相似也可能有独立价值。删除测试后清理不再使用的辅助代码，保留仍有用途的 Fixture；不为迁就测试修改生产行为，不用 `skip` 隐藏失败。

## 必须保护的核心约束

这些约束可以合并重复场景，但不能因缩减数量丢失独立覆盖：

- 阅读位置的保存、恢复与重排；章节跳转、临时返回、取消翻页；Reader 销毁、保存失败、退出保护；离线导航栈与资源释放。
- EPUB/TXT 解析、内容与章节身份、Parser 版本兼容；schema 迁移、事务回滚、重解析位置恢复；托管原件、重复导入与哈希去重、删除及取消的数据安全。
- 重试策略、429 冷却、请求预算与取消、访问限制；缓存淘汰、pin 和清理范围；不可信数据隔离、异步生命周期和资源租约。
- 更新签名、Manifest、SHA-256、未校验包禁止安装、校验失败与取消、正式包发布及恢复、安装前安全验证。

## 按风险安排执行范围

| 级别 | 场景 | 默认执行 |
| --- | --- | --- |
| 1 | 纯视觉或静态文案，没有新行为风险 | 格式、静态分析、必要的实际渲染；可不新增或运行自动化测试 |
| 2 | 普通功能或局部错误映射 | 受影响的单元／数据测试、必要的 Widget 测试和直接调用链回归 |
| 3 | 核心分页与恢复、持久化迁移、导入／删除／缓存生命周期、跨模块所有权、更新安全、较大测试基础设施调整 | 优先相关模块的完整回归，再根据真实影响面判断是否需要全项目回归 |
| 4 | 重要阶段收尾、发布候选验收、大范围测试基建调整、广泛影响的核心架构变化，或用户明确要求 | 完整离线回归 |

日常默认执行定向测试。一个 Widget 改动不自动要求整个 `test/widgets/`；跨文件改动也不自动要求全量测试。禁止将每个小型 UX 修正、每个 Commit 或普通静态页面调整都升级为完整回归。完整回归集中在需要它的收尾节点，不随每个文件重复执行。用户明确要求的验证范围优先。

命令及固定工具链见[开发说明](development.md)。现有日常 CI 保留格式、分析及生成一致性检查，不运行 Flutter 测试；本规范不改变 CI 职责。

## 维护与证据

报告实际执行的命令、范围和结果。区分单元、Widget、浏览器、构建、模拟器与实机证据；未运行、条件跳过、环境受阻和失败均不能写成通过。真实书源检查须遵守[书源访问边界](source/lightnovel.md)。

批量去重时说明被删除或合并的独立场景、重复依据，以及保留用例如何承接原约束。统计区分源码中的测试定义数与矩阵展开后的执行数；比较耗时须注明机器、配置和命令。没有可信旧记录时，不为制造对比重复全量运行。

任务统计、审计过程与验证记录写入最终报告、Commit 或 PR，不写入正式规范。临时截图和诊断证据保持忽略。测试或集成检查改变应用入口、构建参数时，遵守根 AGENTS.md 的记录、恢复和生成配置核对规则。
